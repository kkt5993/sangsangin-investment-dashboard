# PDF 본문·페이지 근거 처리

PRINCIPIUM·IW·ASK의 새 기록과 기존 PDF 첨부에서 제목·저자·페이지별 텍스트를 읽는다. 본문은 기록에 보존하고 검색·페이지 선택·TXT 내보내기·근거 인용을 제공한다. 원문 파일과 연결된 SHA-256, 물리적 PDF 페이지와 문서의 페이지 표기를 함께 보관한다. 작성한 제목·저자·핵심·근거는 추출로 덮어쓰지 않는다.

## 범위와 원본 대응

보존한 리서치 업로드 화면은 PDF·자동 제목·분류·언어·요약 엔진·원문 공개 여부를 받고 서버로 전송한다. 이번 구현은 PDF 읽기·제목/저자·본문/페이지 근거와 보관을 연결한다. 원본과 같은 파일당25MiB 상한을 적용하며 기존8MiB 첨부도 그대로 읽는다. 자동 분류·언어 번역·LLM 요약·공개/비공개 서버 저장 및 인증은 남은 기능이다. 본문 추출을 AI 요약이나 원본 서버 전체 구현으로 표시하지 않는다.

## 파서와 제공 파일

[Mozilla PDF.js 공식 배포 안내](https://mozilla.github.io/pdf.js/getting_started/)의6.3.289를 고정했다. 지원 범위가 넓은 legacy build를 사용하며 [공식 Display API](https://mozilla.github.io/pdf.js/api/draft/api.js.html)의 `getDocument`·`getMetadata`·`getPageLabels`·`getTextContent`를 호출한다. PDF의 실행 코드·폼 동작·외부 링크를 실행하지 않는다. `isEvalSupported=false`, `enableXfa=false`, `useWasm=false`이며 화면의 PDF 처리에서는 페이지 이미지를 렌더링하지 않는다.

파서·worker·CMap·표준 글꼴과 각 라이선스188파일을 같은 웹사이트에 둔다. 첫 PDF 읽기에 필요한 파일만 불러오며 외부 CDN이나 문서 업로드 API를 사용하지 않는다. `scripts/install_pdfjs.py`는 공식 npm tarball의 고정 SHA-512를 검사하고 필요한 파일만 복사한다. `config/pdfjs_vendor.json`의188개 파일 SHA-256·크기와8MiB 배포용 한도를 검증한다. 현재 추가 자산은3,811,556bytes다. Mozilla/Adobe/Foxit 등 패키지에 포함된 라이선스를 유지한다. 다른 프로젝트의 리서치 원문을 공개 배포하는 경로가 아니다.

원문은 파일당25MiB, 글당12첨부, 브라우저 전체64MiB 첨부 한도다. PDF 하나의 텍스트는300쪽·20만 JavaScript 문자열 문자·90초까지 읽는다. 페이지나 문자 한도에 닿으면 완료 범위와 페이지 일부 여부를 표시한다. 유니코드 대리쌍 중간을 자르지 않는다. 물리적 페이지는1부터 연속해서 저장하며 로마숫자 등 문서 페이지 라벨과 구분한다.

## 읽기와 저장

1. 새로 선택한 PDF 또는 저장된 첨부를 선택하고 본문 읽기를 실행한다. 원문 `%PDF-` 서명과 파일 해시를 확인한다.
2. PDF 텍스트 항목 순서·줄 끝과 좌표 간격을 사용한다. 문서의 복잡한 단·표·세로쓰기 순서가 정확히 복원된다고 보장하지 않는다. 원문 다운로드와 함께 확인한다.
3. 페이지를 선택해 본문을 확인하고 필요한 발췌를 근거에 추가한다. 파일명·물리적 페이지·문서 표기·전체 SHA-256이 붙으며 기존 근거는 보존한다. 근거 필드12000자를 넘으면 추가하지 않고 필요한 부분을 줄이도록 안내한다.
4. 저장 버튼을 누르면 PDF 파일·본문·메타·글을 같은 IndexedDB 트랜잭션으로 저장한다. 본문도 전체2MiB 글·메타데이터 한도에 포함된다. 저장 실패 시 이전 데이터와 편집 입력을 유지한다.
5. 저장된 본문도 기록 검색 대상이다. 첨부 포함 백업 버전2는 페이지별 본문을 함께 내보내고 검증해 가져온다. 버전1의 글·첨부를 읽어 보존하며 DB 버전2 업그레이드에서 기존 저장소나 파일을 지우지 않는다. 첨부 연결을 제거하면 연결된 추출 본문도 해당 글에서 제거한다.

파일명이 바뀌어도 같은 바이트의 해시가 원문 연결 기준이다. 추출 본문은 원문 내용의 서명·진위 인증이나 전자서명 검증이 아니다. 수동으로 수정한 백업 내용의 의미가 진실이라고 보증하지 않는다. 공개 팀 노트와 개인 PDF는 분리되며, 정기 PC 계산은 브라우저의 개인 자료를 수집하거나 게시하지 않는다.

## 빈 문서·실패·검증

텍스트 없는 페이지는 스캔/그림 가능성을 표시하고 OCR이 필요하다고 안내한다. 비어 있는 페이지를 문서 요약으로 채우지 않는다. 암호화 PDF는 암호 입력 없이 안내하고, 손상 파일·읽기 취소·시간 초과는 기존 기록을 바꾸지 않는다. 화면을 떠나면 진행 중인 worker를 종료한다.

실제 배포 파서로 합성 영문/한글·숫자·메타·로마숫자 페이지·스캔 페이지·302쪽·암호화/손상 PDF를 검사했다. 문자 한도와 진행 중 취소, 외부 네트워크 요청 금지도 확인했다. 별도 DOM 검사에서 페이지 인용·기존 입력 유지·본문 검색·백업/이전 DB 보존·첨부 제거를 확인한다. 합성 원문과 페이지 이미지, 추출 결과는 로컬 테스트 폴더에만 생성한다.

이번 기능은 실제 로컬 브라우저에서도 PDF 선택→한글 추출→페이지 인용→저장→새로고침→본문 검색과 페이지 전환을 확인했다. 이는 전체25탭의 브라우저 동작·원본 픽셀 일치 검사를 뜻하지 않는다.
