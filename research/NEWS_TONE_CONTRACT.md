# 기업 뉴스 제목 톤

보존 원본의 기업별 news.tone 배지와 tone>0일 때1점 규칙에 대응한다. 원본의 제공처/모형/집계 방식은 공개되지 않았다. 현재는 기존23기업 영문 Yahoo Finance RSS 제목 전체를 독립 분류한다. 기업이 직접 언급되지 않거나 여러 기업이 함께 나온 제목도 있어, 기업별 투자 방향으로 해석하지 않는다.

## 모델과 입력

[ProsusAI/finbert 공식 모델](https://huggingface.co/ProsusAI/finbert)은 금융 문장의 긍정·부정·중립을 분류한다. [개발자 코드](https://github.com/ProsusAI/finBERT)는 긍정확률−부정확률 점수를 사용한다. 공개 모델의 고정 revision4556d13015211d73dccd3fdd39d39232506f3e43과6파일 SHA256을 config/news_tone.json에 기록했다. 가중치·원문은 PC에만 두며 웹사이트/저장소에 재배포하지 않는다. 개발자 코드 라이선스 링크를 함께 보존한다. 제공처의 분류 확률은 교정된 시장 확률이 아니며 주가수익률/호재확률이 아니다.

제목을 Unicode NFC·공백 정규화하고 대소문자는 보존한다. 모델 revision·파일해시·입력계약과 제목의 해시를 캐시 키로 사용한다. 동일 제목이 다른 피드/URL에 있으면 한 번만 계산한다. 제목 정정·모형 교체는 새로운 키다. 영문 피드 범위이며 CJK/일본어/한글 또는 라틴문자 없는 제목은 미분류로 남긴다. 모델의512토큰 입력 범위를 넘는 제목을 잘라 분류하지 않는다. 이는 저장 용량 제한이 아닌 모델 구조의 입력 범위다.

CPU4스레드·16개 배치·eval/inference_mode, float32 softmax. 모델과 토크나이저는 local_files_only, 가중치는 weights_only=True로 읽고6파일 해시를 먼저 확인한다. 가격 모델을 학습/재학습하지 않는다. 외부 추론 API·새 AI세션 호출은 없다. 분류 결과는 원시 확률과 라벨, 차이점수, 토큰수·입력해시·계산시각을 로컬 빈티지에 저장한다.

## 날짜·집계·신호

RSS의 UTC 발행일 기준 최근7일/가격기준일 이하만 집계한다. 미래·과거 제외 뒤, 한 피드 안의 중복 제목을 다시 제거하고 유효한 제목의 점수를 동일 가중 평균한다(−1~1). 긍정/중립/부정 건수는 최대 확률 라벨 건수다. 여러 피드에 중복된 제목이 있으므로 기업별 건수를 더해 전체 뉴스량으로 사용하지 않는다.

피드 성공 수집이36시간 이내·오류없음·주소 일치, 현재 포함 제목이 전부 분류되어 있고 평균>0일 때 ‘연결 제목 톤 양수’1점을 부여한다. 기사8건 조건과 별도이며 독립 신호 확률이 아니다. 미분류가 하나라도 있으면 부분 평균은 보여 주지만 양수 신호를 보류한다. 제목 없는 피드는 평균null이며 중립0으로 채우지 않는다. 오래된 피드의 결과는 보존하지만 새 신호에 넣지 않는다. 기술 신호 가격일과 뉴스 발행일/계산일을 구분하며 과거 시점 백테스트에 소급하지 않는다.

## 파이프라인과 재사용

평일08/18 refresh의 company_news 수집 다음 news_tone을 실행한다. 신규 제목만 분류하며 전부 캐시 적중이면 모델도 불러오지 않는다. 실패하면 이전 결과와 성공 시각을 보존하고1시간 재시도를 유예한다. 정상적으로 계산된 앞선 배치는 실패 뒤에도 저장한다. 모델 파일을 정기 실행에서 자동 다운로드하거나 교체하지 않는다. 데이터 소스의 최근 확인은 현재 집계시각, 마지막 분류시각은 별도로 표시하며 동일 입력 캐시는 시간이 지났다는 이유만으로 무효화하지 않는다.

최초 모델 준비: `python -m pipeline.news_tone --prepare-model`. 이 PC의 전역 huggingface-hub/torchvision 충돌은 형제 sangsangin-investment-tools/news-tone-dependencies에 huggingface-hub0.36.0,tokenizers0.22.1,torchvision0.26.0+cpu를 설치해 격리했다. `SANGSANGIN_TONE_DEPS`로 경로를 변경할 수 있다. Torch2.11.0·Transformers4.57.1을 사용한다. 새 환경은 requirements.txt를 적용하고, 기존 torchvision과 충돌할 때 해당 Torch 버전의 CPU wheel을 전용 폴더에 설치한다. 장애 원인을 수정한 뒤 `--as-of YYYY-MM-DD --retry`로 같은 빈티지의 분류를 명시적으로 재시도할 수 있다.

## 검증과 남은 범위

제목/모델 변경, 중복 제거, 모델 불러오기 없는 재사용, 확률합/라벨/점수, 결측·부분 평균, 실패 보존/재시도, 미래 기사 제외, 날짜가 다른1점 중복 가산 방지, 모델 파일 변조를 검사한다. 실제 모델 추론과 게시값을 대조하고 기사별 확률·피드별 평균·필터·기업 상세·신호 근거·소스카드를 브라우저에서 확인한다.

남은 범위는 전체 기업/제공처·완전한 과거 뉴스·기업을 대상으로 한 문맥감성·모델 교정/정확도 독립 평가·표본 밖 예측력이다. 제목 톤의 구현을 이 전체 범위의 완료로 세지 않는다.
