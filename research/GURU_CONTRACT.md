## 계산과 날짜

포지션은 CUSIP·주식 종류·수량 단위 SH/PRN·PUT/CALL이 모두 같은 행만 합산한다. 원문 행과 다른 운용사/투자재량은 별도 원장에 보존한다. 기업명 유사도만으로 합치거나 주식과 옵션을 합치지 않는다. 비중 분모는 정보표 전체 행의 보고 금액 합계이며 현금·전체 운용자산이 아니다. 옵션 보고 금액은 프리미엄이나 델타 노출이 아니고 옵션 수량을 계약 수로 바꾸지 않는다. [SEC 13F FAQ](https://www.sec.gov/rules-regulations/staff-guidance/division-investment-management-frequently-asked-questions/frequently-asked-questions-about-form-13f)를 함께 참조한다.

현재6공시는 달러 단위 표기를 확인했다. 과거 XML은 단위를 검토한 후 처리하며 금액 크기만 보고1,000배 보정하지 않는다. Duquesne의 원문95행 합5,210,856과 표지5,210,860은4달러 다르다. 행 수는 일치하고 금액 차이는 명시한다. 다른5공시의 정보표 합계는 표지와 정확히 일치한다. Duquesne의 보고 수량 대비 금액 규모는 추가 검토 대상이다. 비중은 정보표 분모로 계산하며 보고 금액을 실제 시장 평가액으로 재검증했다는 뜻이 아니다.

보고일·제출일·접수시각·조회/대조시각을 분리한다. SEC 화면의 시간대 없는 접수시각은 America/New_York로 해석해 UTC로 저장한다. 시세 기준일 이후 제출된 자료는 제외한다. 접수일은 촉매 로그의 날짜이며 분기말 현재의 보유일과 다르다. 확인된 CUSIP의 기업 연결을 제공하며, 구루 보유 +3 신호는 최신 공시 완전성과 분기 공시 시차의 규칙이 검증되기 전에는 보류한다. 주도주/발굴 신호 값은 변경하지 않는다.

정정은 동일 보고기간에서 원보고/RESTATEMENT를 기준으로 이후 NEW HOLDINGS를 합산한다. 원보고 없는 추가 정정은 전체 비중을 만들지 않는다. 13F-NT는 참조 보고이며 빈 포트폴리오로 취급하지 않는다. 공개235행 중 Thiel의 CUSIP000000000·0원·수량0은 원장에만 남기고 포지션 카드에서 제외한다.

## PC 수집과 운영

`pipeline.guru_data`가 기존 평일08/18시 갱신에서 실행된다. 업무용 연락처는 저장소 밖 `sangsangin-investment-data/runtime/sec-contact.json`의 `email`로만 읽는다. 연락처가 없으면 요청0회로 상태를 기록한다. 연락처와 오류 응답 본문은 공개 JSON/로그에 넣지 않는다. 현재 이 PC의 SEC submissions와 Archives 직접 요청은403으로 거부됐으며 반복 우회 요청은 하지 않았다. 연락처 설정만으로403 해결을 보장하지 않는다.

연락처가 준비되면6개 보고 법인의 submissions 최근 목록을24시간 캐시로 확인한다. 최신 보고기간의 원보고·정정을 찾고 신규 접수번호의 표지만/정보표를 받아 XML·주체·날짜·행 수·합계를 대조한다. 기존 접수번호는 재다운로드하지 않는다. 최근 목록에13F가 없으면 과거 보유를 최신으로 승격하지 않고 미확보 상태를 남긴다. 전체 오래된 submissions 파일의 탐색과 연속 분기 변화는 후속 범위다.

요청은1초 간격이며401/403/429는 전체 후속 요청을 중단하고 같은 연락처/구성의 재시도도 보류한다. 일반 오류는24시간 뒤 재확인한다. 실패한 실행은 이전 공시·실제 성공시각을 보존한다. 원자료는 부모 빈티지에서 상속하고 공개 화면은 정적 계산 결과만 읽는다. 용량 검사·저장/전송 상한은 없다.

## 검증과 남은 차이

단위 검사는 XML namespace·CIK/보고기간·정정/NT·행 수·합계 차이·옵션/주식 종류 분리·0원 행·정수 정밀도·시점 제외·403 이후 요청0·연락처 비공개를 확인한다. 초기235행은 보존 SEC 표와 공시별 행 수/합계를 직접 대조한다. 실제 브라우저에서6카드·전체 원장·검색/빈값·옵션 필터·모바일 표시·출처 링크를 검수한다.

6개 법인 확인 공시를 연결했으며 최신 전체13F·연속분기 편입/매도·미대응 CUSIP과 유니버스 밖 기업 확장·구루별 뉴스/관심도·16인 선택 풀과 관리자 설정 반영은 아직 미완이다. 전체 세부탭 목표의 완료를 뜻하지 않는다.

## CUSIP과 기업 상세 연결

`pipeline.guru_identifiers`는 [OpenFIGI 공개 API](https://www.openfigi.com/api/documentation)의 `ID_CUSIP`·`exchCode=US` 대응 결과를 사용한다. API 키 없이5개씩3초 간격으로 요청한다. 공식 문서의 배치 상한이 본문5개/표10개로 다르게 적혀 있어 작은 쪽을 사용한다. 요청/응답 위치가 일치해야 하며 중복 FIGI의 상충 값·다른 시장·누락 필드는 거부한다. 같은 CUSIP에 여러 FIGI가 나오면 임의 후보를 선택하지 않는다.

단일 FIGI의 티커를 현재 미국 기업 상세 심볼과 정확히 대조한다. 주식 종류 구분자의 `/` 또는 `.`→`-`만 시세 코드 관례에 맞게 바꾸고 이름 유사도로 합치지 않는다. 보통주·ADR/GDR·REIT·NY registered shares·MLP를 허용하며 ETP/Closed-End Fund는 기업 카드에 연결하지 않는다. SH 수량만 연결하고 PRN은 제외한다. PUT/CALL은 같은 기초종목으로 이동하되 **옵션 포지션**이라고 표시한다. Alphabet A/C 및 우선주, 기초주식/옵션의 보고 금액을 임의로 합산하지 않는다.

성공 대응은30일, 식별자 미확보·다중 후보는7일 캐시다. 최초5개 진단 결과를 재사용하고 나머지148개 식별자를30배치로 수집했다. 총153개 결과 중140개는 단일 대응,13개는 미확보다. 전체 공시의173개 합산 포지션 중 현재 기업 상세에73개 포지션·57기업을 연결했다. 나머지는 유니버스 밖·다른 증권 유형·미확보 사유를 각각 표시한다. 재실행은0요청이었다.

실패한 응답은 이전 정상 식별자/확인시각을 보존한다. HTTP401/403/429는 후속 배치를 중단하고 오류 실행은1시간 재요청을 보류한다. 오래된 성공 관측이30일을 넘으면 기업 연결에서 제외하며 공시 자체는 유지한다. 식별자 원응답·캐시는 PC `guru/identifiers.json.gz`에 저장한다. 평일08/18 갱신에서13F 수집 뒤 실행한다. 용량 검사는 수행하지 않는다.

식별자 확인시각은 보고 분기말과 별개다. 현재 식별자 응답은 과거 특정일의 티커/상장 상태를 보증하지 않으므로 PIT 백테스트나 신규 매수 신호에 사용하지 않는다. 기업 상세에는 보고 법인·보고/접수일·포지션 종류·수량·해당 공시 비중·CUSIP/FIGI·대응 확인시각과 두 원문을 표시한다. 스마트머니 카드와 표에서 기업 상세로 이동한다.
