# PDF 파서·선택 OCR·페이지 근거

PRINCIPIUM·IW·ASK의 PDF 첨부를 브라우저에서 읽고 제목·저자·페이지 본문·물리적 페이지·문서 페이지 표기·원문 SHA-256을 보존한다. 작성자가 입력한 제목·저자·핵심·근거는 덮어쓰지 않는다. 본문 검색·TXT 내보내기·페이지 인용·첨부 포함 백업을 제공하며 문서를 외부 API에 보내지 않는다.

## 처리 방식

- **자동(기본)**: PDF.js를 먼저 사용한다. 문자 매핑 오류가2%를 넘거나 본문이 없거나, 큰 이미지가 페이지 절반을 넘으면서 본문이 짧은 경우만 렌더링·OCR한다. 짧은 정상 표지와 빈 페이지 때문에 OCR 모델을 불러오지 않는다.
- **파서만**: 디지털 PDF의 텍스트를 빠르게 추출한다. 스캔의 글자는 얻지 못한다.
- **전체 OCR**: 본문이 있는 페이지도 영상으로 읽는다. 이미지 속 내용이 자동 판별에서 빠지거나 글꼴 매핑이 잘못된 경우 선택한다.

언어는 한국어+영어 또는 영어, 배치는 한 단 또는 여러 단을 선택한다. 기본은 한 단(PSM6), 여러 단은 자동 배치(PSM3)다. 복잡한 표의 셀·읽기 순서를 정확히 복원한다는 의미는 아니다. 혼합 페이지의 텍스트가300자 이상이면 이미지 속 추가 본문이 자동 판별에서 빠질 수 있으므로 전체 OCR과 비교한다.

## 비교 실험과 선택

2026-09-10 이 PC의 Edge152에서 동일한 합성 금융 문서6쪽을 비교했다. 영문·한글 디지털 각1쪽, 그 페이지의200dpi 스캔 각1쪽, 짧은 표지와 한글 스캔의 혼합1쪽, 빈1쪽이다. 정답 문장·숫자를 직접 생성했다. 실제 증권사 보고서 전체·복잡한 표·회전 스캔의 정확도를 대표하지 않는다. 시간은 설정별1회 측정이며 환경·문서에 따라 달라진다. 파서는 첫 로딩을 포함하고, 300dpi 전체/자동 비교는 같은 브라우저에서 모델 캐시가 있는 상태다.

| 방식 | 6쪽 시간 | OCR 페이지 | 숫자25개 정확 문자열 일치 | 최대 페이지 문자 오류율 |
|---|---:|---:|---:|---:|
| 파서만 | 0.32초 | 0 | 10/25 | 스캔 본문 누락 |
| 전체 OCR · 한/영 경량 · 216dpi | 8.13초 | 5 | 22/25 | 4.40% |
| 전체 OCR · 한/영 경량 · 300dpi 상한 | 9.82초 | 5 | 22/25 | 2.96% |
| 선택 OCR · 한/영 경량 · 300dpi 상한 | 6.43초 | 3 | 23/25 | 2.96% |
| 전체 OCR · 한글 정밀/영어 경량 · 300dpi 상한 | 13.73초 | 5 | 23/25 | 4.40% |
| **선택 OCR · 한글 정밀/영어 경량(채택)** | **9.11초** | **3** | **24/25** | **2.46%** |
| 채택 설정의 완료 페이지 재사용 | 0.16초 | 0 | 24/25 | 이전 인식문 보존 |

문자 오류율은 NFKC 정규화·공백 제외 문자열의 편집거리/정답 길이다. 숫자는 1,234.50, -123.45, -5.25%, 2.50%, 2026-09-08의 페이지별 정확 일치다. 채택 설정의 한 오류는 혼합 페이지에서 1,234.50을 1234.50으로 읽어 쉼표가 빠진 경우다. 경량 모델은 한글 스캔에서11234.50처럼 숫자값도 바뀌었다. 자동 교정으로 정답을 끼워 맞추지 않는다. 문장 일부의 한글/영문 혼동도 남아 있다.

파서는 정상 본문2쪽의 문자 오류0을 보존한다. 채택한 선택 OCR은 같은 정밀 모델의 전체 OCR보다 약34% 빨랐고 렌더링 화소는40% 적었다. 같은 파일 재사용에는 OCR·렌더링이 없다. 한국어 정밀 모델은 압축 파일이 약10MiB 크지만 숫자·본문 품질을 고려해 채택했다. 인식 점수는 문자 정확도 확률이 아니며 숫자·표는 원문 대조 후 사용한다.

재현 스크립트는 scripts/make_ocr_fixtures.py(개발용 reportlab·PyMuPDF), scripts/benchmark_pdf.cjs(개발용 Playwright·로컬 Edge)다. 원문·정답·이미지·측정 JSON·화면은 저장소 밖 runtime/pdf-ocr-fixtures/에만 생성한다. 브라우저의 외부 요청을 차단해 시험했다. 정기 갱신마다 무거운 벤치마크를 다시 실행하지 않는다.

## 엔진·캐시·자원 한도

[PDF.js 공식 API](https://mozilla.github.io/pdf.js/api/draft/api.js.html)의6.3.289 legacy build, [Tesseract.js6.0.1 API](https://github.com/naptha/tesseract.js/blob/v6.0.1/docs/api.md)와 core6.0.0을 고정한다. 영어는 [tessdata_fast4.1.0](https://github.com/tesseract-ocr/tessdata_fast/tree/4.1.0), 한국어는 [tessdata_best4.1.0](https://github.com/tesseract-ocr/tessdata_best/tree/4.1.0)다. Apache-2.0 라이선스와 번들 의존성 고지를 포함한다.

- OCR 자산은11파일21,660,329bytes다. npm SHA-512 및 파일별 SHA-256·크기·목록을 설치/검증/배포에서 검사한다. 임의 바이너리는 허용하지 않는다. PDF 파서는188파일3,811,556bytes다.
- 페이지 탐색 시 OCR 자산을 미리 내려받지 않는다. 처음 필요한 때 같은 사이트에서 받는다. 영어 전용은 한국어 모델을 내려받지 않는다. 언어 모델의 브라우저 캐시 키에 모델 버전을 포함한다.
- [공식 성능 안내](https://github.com/naptha/tesseract.js/blob/v6.0.1/docs/performance.md)에 따라 한 문서의 worker를 재사용하고 페이지를 순차 처리한다. LSTM만 실행하며 SIMD/비SIMD 두 LSTM 코어를 제공한다. 사용하지 않는 legacy 코어는 배포하지 않는다.
- 기본300dpi·캔버스800만 화소 상한이다. A4는 실제 약287dpi다. 한 페이지씩 처리 후 캔버스·페이지 자원을 해제하고 완료/취소 때 worker를 종료한다. 800만 화소 RGBA 캔버스는 약32MB이며 브라우저 전체 메모리 상한이라는 뜻은 아니다.
- 파일·첨부·본문/메타·백업의 용량 상한과 합산 검사는 제거했다. 언어 모델 캐시는 재사용한다.
- 문서당300쪽·20만 JavaScript 문자열 문자. 파서90초, OCR 포함180초. OCR은 회당30쪽이며 남은 페이지는 대기로 표시한다. 다시 읽으면 완료 페이지를 재사용하고 다음30쪽을 처리한다. 문자/쪽수 한도는 계속 적용된다.
- 원문 해시·처리 버전·모드·언어·배치·DPI가 같을 때만 완료 페이지를 재사용한다. 실패·대기·잘린 페이지는 다시 처리한다. 파서/OCR/빈 페이지/대기/실패 상태, 인식 점수·시간·실제 DPI를 저장·백업한다.

PDF의 실행 코드·폼 동작·외부 링크는 실행하지 않는다. isEvalSupported=false, enableXfa=false, PDF.js useWasm=false이며 OCR은 별도 고정 WebAssembly LSTM을 사용한다. OCR 때만 PDF 페이지를 렌더링한다.

## 저장·실패·검증

저장을 눌러야 PDF·본문·글이 동일 IndexedDB 트랜잭션으로 보존된다. 해시·페이지·본문 길이·처리 메타를 검사한다. 기존 백업 버전1/2와 OCR 이전 추출도 보존하며 파일명 변경으로 원문 연결이 끊기지 않는다. 원문 해시는 파일 연결 기준으로, 내용의 진실성·전자서명 인증은 아니다.

OCR 실패는 그 페이지의 파서 본문을 보존하고 재시도를 표시한다. 취소·암호화·손상·시간 초과는 기존 저장 기록과 편집 입력을 바꾸지 않는다. 초기화 중 취소된 OCR worker도 초기화가 반환되는 즉시 종료한다. 빈 문서에 요약을 만들지 않는다.

오프라인 회귀 검사는 자동 선택, 단일 worker, 재사용/설정 변경,30쪽 이어 읽기, 실패 본문 보존, 취소, 미세한 비백색 화소, 메타 변조·백업을 검사한다. 실제 로컬 브라우저에서는 선택→OCR→페이지 근거→저장→새로고침→본문 검색→캐시 재사용을 확인했다. 원문 업로드 요청은0이다.

자동 분류·번역·LLM 요약, 팀 공용 DB·인증·공개/비공개 서버 저장과 서버 방문 통계는 남은 별도 기능이다. PDF 추출을 AI 요약이나 전체 서버 구현으로 표시하지 않는다.
