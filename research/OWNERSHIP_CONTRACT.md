# 내부자 매수 원장과 카드

보존한 원본의 전략 화면은 종목별 미니 가격선, 복수 매수자 배지, 건수·금액·저점 대비 값을 카드에 표시한다. 팀 화면은 같은 카드 구조에 검색·보고주체 필터와 공시 원장을 연결했다. 원본 스냅샷의 종목·수치는 재게시하지 않는다.

## 포함 기준과 단위

- 기간은 가격 기준일을 포함한 **90개 달력 날짜**다. 미국 동부 날짜의 다음 날00시 전에 접수된 Form4만 포함한다. 거래 날짜와 공시 날짜를 따로 보존한다.
- 비파생 거래 행의 **코드P·취득A·양의 수량·양의 가격**만 집계한다. 보유 잔고 행, 파생상품, 매도·보상·행사·증여는 제외한다. P는 공개시장과 사적 매수를 모두 포함하므로 공개시장 거래만이라고 표현하지 않는다. [SEC Form4 지침](https://www.sec.gov/files/form4.pdf).
- 공시 수는 고유 accession 수, 거래 수는 포함된 거래 행 수다. 보고주체 수는 고유 보고자 CIK 수이며 관련 법인·공동보고자의 경제적 독립성을 뜻하지 않는다. 2개 이상이면 배지를 표시한다.
- 금액은 공시 수량×공시 가격의 합을 USD백만으로 표시한다. 수수료를 포함한 실제 현금 결제액이 아니다. 가중평균 가격 주석은 별도 표시한다. 제공처가 반올림한 금액은 원문과1달러 이내일 때만 금액 일치로 표시한다.
- 미니 가격선은 최근63개 수정종가를 최대44점으로 표시한다. 저점 대비는 최근252개 수정종가의 최솟값 기준이며 장중52주 저가와 다르다. 252개가 없으면 저점 대비를 계산하지 않는다.
- Form4/A는 자동 합산하지 않는다. 같은 발행사·보고자이고 원 공시일 또는 거래일이 겹치는 원본도 별도 대조 전까지 집계에서 제외한다. 아직 정정 관계를 완전히 해소하는 엔진은 없다.

## 접수와 가격 시점

색인의 Accepted는 미국 동부시각을 DST에 맞춰 UTC로 변환한다. 자동 API의 시간대가 명시된 접수시각은 해당 시간대를 유지해 변환하며, 시간대 없는 값은 추측하지 않는다. 거래 원문 XML에는 접수시각이 없어 제출 목록 또는 별도 색인과 연결해야 한다.

D0는 접수 후 첫 정규장 종가다. 동부16시 이후면 다음 실제 거래일로 넘기며 휴일에는 다음 관측일을 쓴다. D0반응은 직전 종가 대비, D+5/20과 SPY 초과는 D0종가 이후의 거래 관측 기준이다. 기준일까지 만기가 오지 않았으면 빈칸이다. 조기 폐장일의 별도 장종료 달력은 아직 연결하지 않았으므로 이때의 장중 접수 연구는 추가 검증이 필요하다.

SEC 접수와 웹 최초 공개시각은 동일하다고 보장할 수 없다. 이는 가격 관측이며 당시 실행 가능한 매매 성과나 인과 효과가 아니다. 이번 원문은 현재 확인한 역사 공시이므로 당시 수집한 PIT 기록으로 주장하지 않는다. [SEC 웹마스터 FAQ](https://www.sec.gov/about/webmaster-frequently-asked-questions).

## 출처와 현재 범위

`config/sec_ownership_reviews.json`은 공개 SEC 거래 원문과 색인을 사람이 대조한 사실 기록이다. 주소·연락처는 보관하지 않는다. `source_url`·`index_url`·`retrieved_at`·`mode`를 각 공시에 남긴다. 이 파일은 매번 자동 갱신되는 데이터가 아니다. 이후 직접 XML을 수집하면 같은 accession을 덮어 써 중복을 막는다.

2026-09-08 기준 제공처 후보8행을 대조했다. 접수시각 확인7공시·9거래 행·4기업(PFE/CVNA/VST/CEG)을 집계했고, AVGO1공시는 접수시각 미확보로 제외했다. VST의 제공처1행은 실제8월31일·9월1일의2거래 행이며, CVNA1행도 같은 날 서로 다른 공시 가격의2행이다. 원문에 없는 시각을 서명일로 대신하지 않는다. 전체 미국 시장을 조사한 결과가 아니다.

직접 수집기는 이벤트 기업 집합에 대해 종목/CIK 목록1회→기업 제출목록→새 Form4/4A XML 순서로 조회한다. 제출목록은 최근120일을 선별하고 회당 최대300개 새 문서를 받는다. 최근 제출목록에 필요한 기간이 모두 없으면 partial이다. 추가 과거 제출목록 다운로드는 아직 없다. [SEC 제출목록 API 범위](https://www.sec.gov/search-filings/edgar-application-programming-interfaces).

2026-09-09 UTC PC의 종목 목록/제출목록 시험은 HTTP403이었다. 자동 조회가 성공한 것처럼 표시하지 않는다. 예약 파이프라인에 수집기를 연결하되401/403/429에서는 전체 시도를 즉시 중단하며, 기록 시각으로24시간 안에는 반복하지 않는다. 별도 계정·프록시·유료 API는 사용하지 않는다. 이전 공시는 나이를 보존한 채90일 창에서 자연스럽게 제외된다. 새 자료가 없다고 과거 거래일을 새 날짜로 바꾸지 않는다.

원자료와 압축 XML·제출목록·실패 상태는 PC의 로컬 캐시에 보관한다. 웹사이트를 열 때 SEC나 원본 사이트에 요청하지 않는다. 기존 평일08시/18시 실행 중 하루 단위 갱신을 시도한다. 전체 연속 수집, Form4/A 정정 확정,13F와 비용 후 OOS는 남은 작업이다.

## 검증

Python fixture는 XML 네임스페이스·코드/취득·잔고 배제·개인 주소 제외·CIK 불일치·XML 크기/엔티티·시간대·90일 경계·미래 접수·정정·중복·거래일 합산·403 중단/24시간 간격을 확인한다. 공개 JSON은 원문 금액 합계·보고주체/공시/행 수·날짜·가격 점 수를 검사한다. JavaScript는 실제 출력 렌더링과 독립 fixture의 검색·복수 보고주체 필터·상세 버튼·빈 결과·이스케이프를 확인한다. fixture는 정기 갱신에 따라 표본이 바뀌어도 작동하도록 날짜를 고정했으며 배포 데이터로 쓰지 않는다.
