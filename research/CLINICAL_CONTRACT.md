# 임상시험 등록부 관측 계약

DRAGONGLASS 보존 데이터의 비만·GLP-1, Eli Lilly, UnitedHealth 세 범위를 [ClinicalTrials.gov 공식 API](https://clinicaltrials.gov/data-api/api)로 독립 수집한다. 원본의 검색식과 필터는 공개되지 않아 건수 동일성을 주장하지 않는다. 현재 검색식·범위·기관별 포함 조건은 `config/clinical_scopes.json`과 화면에서 확인한다.

## 정의와 날짜

- 전체: 명시한 질환/중재 또는 책임 스폰서/공동기관 검색 결과. 기업의 모든 계열사·라이선스 자산을 포괄하지 않는다. 비만·GLP-1 검색에는 생활습관·관찰 연구가 포함된다.
- 모집 중: `filter.overallStatus=RECRUITING`. 아직 모집하지 않음/진행 중이나 모집하지 않음 상태는 제외한다.
- 3상: 기본 검색과 `AREA[Phase]PHASE3`의 교집합이며 모집 상태는 제한하지 않는다. Phase2/Phase3 복합 표기도 포함할 수 있다. 모집 중 건수와 별개 집합이므로 합산하거나 모집 중3상으로 읽지 않는다.
- 건수는 공식 응답 `totalCount`, 목록은 `LastUpdatePostDate:desc` 상위5건이다. 전체 연구 목록을 받은 것이 아니다. NCT ID·공식 링크·제목·상태·단계·책임기관·공동기관·기록 갱신일을 보존한다.

공식 필드의 의미는 [Study Data Structure](https://clinicaltrials.gov/data-api/about-api/study-data-structure)를 따른다. 기록 갱신일은 연구 시작·완료·결과 발표일과 다르다. `dataTimestamp`는 API가 제공한 시간대 없는 문자열을 그대로 표시하고 UTC라고 추정하지 않는다. 성공 수집/최근 확인은 명시적 UTC 시각이며 시장 가격 기준일과 별개다. 등록부 상태·단계 자체로 임상 성공·허가·기업 수익을 판정하지 않는다.

## 수집·재사용·검증

`pipeline.clinical_data`는 가격 전체를 메모리에 적재하지 않고 기존 빈티지 경로만 해석한다. 평일08/18 refresh에 연결하며 성공확인 후24시간은 네트워크0회, 이후 API 버전이 같으면 버전1조회만 하고 자료를 재사용한다. 데이터 버전이 바뀌면 시작/종료 버전2조회와3범위×3조건9조회,총11회다. 요청 간1초,타임아웃10/30초,리다이렉트/인증/유료API가 필요하지 않다. 추가 원본사이트 요청은0회다.

조회 중 등록부 버전 변화,HTTP 오류,건수/표본/식별자/필터/단계/정렬/미래 갱신일 불일치 시 해당 실행 전체를 실패 처리한다. 이전 성공 건수·기록·성공시각·검색식을 보존하고1시간 재시도를 미룬다. 실패한 새 검색식 결과에 옛 건수를 붙이지 않는다. 첫 관측이나 검색식 변경 후 증감은 null,이후는 전회 성공 수집 건수 대비 차이다. 건수 변화의 원인은 등록·상태 변경·수정 등으로 다양하며 신규 임상시험 수가 아니다.

원응답·정규화·검색URL·API 버전은 로컬 변경분 빈티지 `clinical/observations.json.gz`에 저장한다. 전체 시세를 복제하거나 저장 용량을 검사하지 않는다. 공개 JSON에는 세 범위의 집계와5건씩의 지정 필드만 내보낸다. 표시할 때 시세/API 호출을 하지 않는다.

## 화면과 남은 범위

트리거 화면은3범위 카드·세 가지 건수·전회대비·검색식·조건별5연구·기업 상세와 원문 이동을 제공한다. 모집 중 건수가 양수인 범위는 촉매 원장에 최근 연구 기록 갱신일과 함께 들어간다. 임상 건수를 주가 신호 가중합에 추가하지 않는다. UNH처럼 모집 중0건도 카드에서0으로 표시한다.

원본의 정확한 검색식/기관별 인수·자회사 범위,전체 연구별 변화 이력·신규 모집 알림·규제 승인·임상 결과 해석은 남은 범위다. 13F·기업 뉴스 감성·관심량과 비공개 정량 투자뷰도 별도 구현 대상이다.

이번 임상 전용 배포는 가격·Overview 계산을 재사용하므로 status의 계산 빈티지는 이전 값을 유지한다. 새 임상 원자료는 supplemental_vintages.clinical과 임상 섹션 source_vintage에 별도 추적하며,다음 전체 갱신은 새 부모 빈티지에서 모든 모듈을 다시 계산한다.
